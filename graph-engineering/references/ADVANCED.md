# Advanced Supplement (GRAPH_RULES 보완)

GRAPH_RULES.md에 없는 실전 기법. 병렬 규모가 크거나 검증이 중요할 때 반드시 읽을 것.

## 1. Verifier Fresh-Context + 3-Lens
- 검증자는 작업자의 대화/컨텍스트를 절대 공유하지 않는다. 산출물(요구사항 + diff/아티팩트 + 테스트 출력)만 받는다. 공유하면 "같은 루프가 자기 숙제를 채점"하는 것과 같다.
- 중요한 발견은 서로 다른 질문의 3개 렌즈로 병렬 검증:
  1. 정확한가? (주장이 실제로 성립)
  2. 최신인가? (근거가 오래되지 않음)
  3. 근거가 실재하는가? (인용 파일/라인/링크가 실제로 그 주장을 뒷받침)
- 다수결 통과만 생존.

## 2. Anchors (앵커)
모든 노드가 서로의 **보고서**만 검사하면 전부 일관되지만 아무것도 검증되지 않는다.
그래프에는 반박 불가능한 노드가 최소 1개 필요:
- 실제 실행되어 통과한 테스트 출력
- 실측 데이터 (DB 쿼리 결과, 기계 카운터 값)
- 동결 규칙 (최적화가 건드릴 수 없는 불변 조건 — 예: 품질 판정 기준치 수정 금지)

> 토폴로지는 진실을 사지 못한다. 앵커가 산다.

## 3. 대규모 Fan-in 트랩 2종
| 트랩 | 해법 |
|---|---|
| **Context Collapse**: 대량 fan-out 결과를 한 번에 종합하다 컨텍스트 초과 | **계층형 fan-in**: 배치(예: 40개)별 요약 → 요약들만 최종 종합. 원본 더미 직접 투입 금지 |
| **Silent Node Failure**: 그래프에서는 노드 하나가 죽어도 보고서가 완성된 것처럼 보임 | **Fan-in Guard**: 종합 노드는 `받은 입력 수 == 기대 수` 검사. 부족하면 경고 후 중단, 부분 데이터로 종합 금지 |

## 4. 모델 티어링 (비용)
- 단순/기계적 노드(수집, 포맷 변환) → 저가 모델
- 판단 노드(검증, 종합, 설계) → 고성능 모델
- reduce는 가능하면 모델 없이 코드로 (dedupe, filter, count)
- 멀티에이전트는 채팅 대비 토큰 수 배~15배. **그래프는 폭(breadth)을 사는 것이지 판단력을 사는 게 아니다.**

## 5. Dynamic Discovery 종료 규칙
규모를 미리 모르는 작업(버그 스윕 등):
- 발견자 병렬 → 기존 발견과 dedupe → 검증 → **연속 2라운드 신규 발견 0이면 종료**
- 총 에이전트 수 하드캡 필수 (폭주 방지)

## 6. Loop → Graph 승격 철학
처음부터 그래프 금지. 최소 루프로 시작 → 실패 지점 관찰 → 안정 구간만 그래프로 승격.
계층 구분: 환경 문제 → 하네스 / 종료 조건 문제 → 루프 / 전이·분기 문제 → 그래프.

## 7. Claude Code 실행 팁
- 프롬프트를 **"workflow"** 로 시작하면 오케스트레이션이 코드로 작성되어 중간 결과가 메인 컨텍스트를 소모하지 않음
- 서브에이전트 frontmatter `tools:`로 권한 제한 (감사 노드는 `Read, Grep, Glob`만)
- 잘 나온 실행은 `.claude/commands/`에 저장하여 재사용
